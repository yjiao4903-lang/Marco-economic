# D2/D4 生产落地与 release gate 决策简报

**日期**：2026-09-01（Asia/Shanghai）
**对象**：D2 `CN_TSF_TOTAL`、D4 `CN_GOV_BOND_FINANCING`

## 结论

D2/D4 的生产替换动作已经落地；负责人现已接受公开累计报告差分的分辨率感知门，
因此 release gate 状态为 **conditionally accepted**，但不是无条件 PASS：
2018-01..2026-03 已使用 Wind 历史，2026-04..07 的 PBC 生产尾部保持不变；
生产 ID、下游路由未改，候选序列仍保留，并已生成回滚备份和重建 DuckDB。

当前应记录为：**生产已落地，release gate = conditionally accepted**。

## 两种门检验的对象不同

| 门 | 直接比较的对象 | 阈值/依据 | 结果与含义 |
|---|---|---|---|
| 分辨率感知门 | Wind 候选月度流量 vs PBC 公开累计值差分候选（2026-04..07） | `abs diff <= 10 bn_cny`；PBC 公开累计值分辨率为 0.01 万亿元，即约 10 bn_cny | D2 最大差 **8.3 bn_cny**、D4 最大差 **5.9 bn_cny**，各 4/4 通过。说明差异未超过公开数据的显示/舍入分辨率；不单独证明字段定义、单位和修订口径完全一致。 |
| 严格 live PBC tail gate | Wind 候选 vs 已落地生产中的 PBC live tail | 共同月份不少于 3、100% 覆盖、月末对齐，且逐月 `abs diff <= 0.1 bn_cny` 或相对误差 `<=0.5%` | 这是历史文档定义的高精度可比性门。当前材料尚未证明该门通过，因此不能据此宣称无条件 PASS；若坚持该门，release 仍为 BLOCKED/待补证据。 |

差异的核心不是“同一门一正一负”，而是两道门的测量对象和容差不同：前者接受公开累计值的量化分辨率，后者要求 live 尾部在更细精度下可比。

## 已核对事实

- 实际 apply 记录为 `APPLIED`，历史窗为 2018-01-31..2026-03-31；PBC 尾部未覆盖，备份目录为 `data/local/promotion_backup_20260831_210503`。
- 生产 ID 与路由保持不变；Wind 候选仍保留；这不是把候选直接改名后接入新路线。
- 分辨率感知对照来自公开累计值差分，不能替代原始 PBC 报告、发布日期、字段定义、单位和修订链审计。
- 工作区另有严格门/重算诊断材料指出，若把不同单位或尚未完成原文复核的 PBC 观测直接与 Wind 月流量比较，会出现数量级差异；这强化了“门的对象必须写清”的要求，但不单独判定本次已落地序列错误。

## 已确认决策

1. **接受分辨率感知门作为本次 release gate**：D2/D4 标为“有条件接受/已落地”，适用范围限定为公开累计报告差分；保留来源转换、10 bn 分辨率限制和后续复核任务。不得将其描述为高精度同口径已证实。
2. **严格 live-PBC tail gate 继续独立保留**：它是原始解析验收门，仍需原始 PBC 报告、字段/单位/发布日期与逐月对照证据；本次 release 接受不代表该门通过。

## 本简报不授权的事项

不修改 canonical、DuckDB、配置或信号定义；不重复执行 `promote_d2_d4.py --apply`；不把任一门的通过扩大为 D2/D4 无条件 PASS，也不把解析/结构测试当作语义等价证明。
